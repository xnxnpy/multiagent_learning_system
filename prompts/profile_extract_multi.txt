## 可提取的 8 个维度

| 字段 | 含义 | 合法值说明 |
|------|------|-----------|
| major | 专业 | 学生原话中的专业名，如计算机、软件测试 |
| grade | 年级 | 仅允许：大一、大二、大三、大四、研一、研二、研三、博士。「大2」写成「大二」 |
| goal | 学习目标 | 如考研、找工作、课程需要 |
| knowledge_level | 知识水平 | 如零基础、有编程语言基础、学过相关课程、有一定基础 |
| learning_style | 学习风格 | 仅允许：看视频、看文档、动手实践、做题 |
| coding_ability | 编程能力 | 仅允许：零基础、入门、会基础语法、中级、熟练、精通 |
| interests | 兴趣方向 | JSON 数组，学生明确提到的方向 |
| weakness | 薄弱点 | JSON 数组，学生明确表示薄弱的内容 |

## 关键区分（必背）

- **「有编程基础 / 有编程语言基础 / 有一定基础 / 学过编程」** → 同时输出：
  knowledge_level = 学生原话可保留（如「有编程语言基础」），**且**
  coding_ability = 入门（除非学生说中级/熟练等更明确的级别）
- **knowledge_level** = 对当前学习领域的整体了解程度
- **coding_ability** = 具体的编程技能等级（枚举）
- 「零基础 / 没学过」→ knowledge_level 保留原话，coding_ability = 零基础
- 「我想考研 / 找工作」→ goal，不是 major
- 「计算机 / 软件测试专业」→ major，不是 grade
- 「数学差 / 算法弱」→ weakness

## 其他规则

1. 只提取学生明确说出的，禁止推断脑补
2. 学生没说的维度不要输出（字段缺失，不是空字符串）
3. 若当前最需要的维度是 X，且回答能归入 X，优先保证 X 有输出
4. 只输出一个 JSON 对象
